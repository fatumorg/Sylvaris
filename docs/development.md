# Working on Sylvaris

```sh
git clone https://github.com/fatumorg/Sylvaris
cd Sylvaris
bin/install-hooks
nix develop
node --test tests/*.test.mjs
nix flake check
tests/headless/all.sh
```

`bin/install-hooks` copies the git hooks from `bin/hooks` into `.git/hooks`. Run it once after cloning and again whenever they change.

## How it is built

Each directory under `shell/` is a QML module with an entry file named after the part. Logic lives in `shell/lib/*.mjs`: plain JavaScript with no QML, unit-tested in `tests/`. Services in `shell/services/` are singletons that parts share. [ARCHITECTURE.md](../ARCHITECTURE.md) explains how the pieces fit together, and [CONTRIBUTING.md](../CONTRIBUTING.md) covers the conventions.

## Headless tests

`tests/headless/run.sh` starts a headless sway with no visible output, runs Sylvaris inside it with `SYLVARIS_DEMO=1` (fixture devices instead of real ones), drives it over IPC and saves screenshots. It never touches your real devices or screens.

```sh
tests/headless/run.sh tests/headless/out/compact tests/headless/compact.steps tests/fixtures/seed/warm
```

It renders in software by default. Set `HL_RENDERER=gles2 HL_QT_BACKEND=rhi` to render with OpenGL, which texture-filled shapes such as album art need. `docs/design/reference.html` is the visual source of truth.

## Measuring

`tests/bench/bench.sh` measures memory and CPU the same way the numbers in the README were taken. `BENCH_SETTINGS` takes a `settings.json` to compare setups.

## This documentation

The pages in `docs/` are plain Markdown and read the same on GitHub and on the website. `docs/reference/settings.md` is generated by `node site/reference.mjs`, and the capability table in [compositors](compositors.md) by `shell/lib/wm.mjs`; tests fail when either is out of date. `site/` builds the website from these files (see its README).
